1. Design principles

  1. Built for the sideline. Used one-handed, standing, in sunlight, while watching kids. Big tap targets, high contrast, light theme, very little text entry during a game.
  2. Tap, then tap. Lineup changes are always "tap a player, then tap where they go" (a slot or another player to swap with). No drag-and-drop. It's more reliable on phones and works with gloves on.
  3. The clock never blocks you. The game clock keeps running whatever screen you're on. Recording a sub takes one tap at the stoppage, because the prep happens beforehand.
  4. Fairness visible at a glance. Every player chip shows that player's minutes this game. Bench players are sorted with the fewest minutes first.
  5. Mistakes are cheap. Every action has a short Undo, and the whole game can be edited afterward. Coaches should never hesitate to tap.
  6. Coaches decide. The app records and shows data. It doesn't suggest lineups or enforce rules.

2. Glossary & player states

TermMeaning
RosterAll players on the team for the season. First name + last initial(s). Initials can be more than one letter to tell apart two players with the same name.
PresentThe player showed up for this game. Set before the game, and can be set mid-game for a late arrival.
On field / BenchWhere a present player is right now.
Available / UnavailableWhether a present player can go in right now (injury, sick, bathroom, etc.). Tracked as time windows.
StintOne player's continuous time on the field, from coming off the bench until going back to it. Position moves don't end a stint.
ShiftThe stretch of time between two subs. A game is a sequence of shifts, and each shift has one lineup.
Next UpThe queued lineup for the next shift. Built while play continues, then applied with one tap ("Sub now") at a stoppage.
Positions7v7: GK, LB CB RB (defenders), LF CF RF (forwards). Stored as config so the formation can change later.

State layers for a single player in a game

Roster→ Present?→ On field (position) / Bench× Available / Unavailable

Every minute a present player spends in a game falls into exactly one bucket. These buckets drive all the stats:

On field (per position) Bench, available Bench, unavailable

A player on the field who becomes unavailable is subbed off at that moment (see §9), so "on field + unavailable" never happens.

4. Roster

Set up once at the start of the season and rarely touched after that.

5. Games list

  1. The home screen. A live game is pinned to the top and shows its clock, so after reopening the app you're one tap from the game.
  2. + New game asks for date/time, opponent and optional location. That's all.
  3. Tapping a game opens the view that matches its state: pre-game, live or review.
  4. Scores are not shown (out of scope).

6. Pre-game: attendance & starting lineup

Two quick steps before kickoff. Both can be done at home the night before (starting lineup) or at the field (attendance).

Interaction (used everywhere a lineup is built):
  1. Tap a player (slot or bench chip). It gets a blue outline.
  2. Tap a target: an empty slot moves them there, a filled slot or bench chip swaps the two.
  3. Tap the selected player again to cancel.
"Start 1st half" works even with empty slots (in case you're short players). The app warns you but doesn't block.

7. Live game

The main screen of the app. It has a pinned clock at the top and a On Field / Next Up toggle. The field and bench below always show the selected view.

Anatomy

  1. Clock bar. Dark, sticky, big monospace digits, readable at arm's length. Counts up from 0:00 each half and keeps going until the coach taps End half (or End game in the 2nd half). Halves don't have to be exactly 30:00.
  2. ⋯ menu: End half / End game, Pause clock (rarely needed, the clock normally runs nonstop), Adjust clock (if the app was started late), Dim mode, Game timeline.
  3. Field. Attack is up. Each slot shows position, name, stint (time on the field since they last came off the bench) and game total: on 8m · 18m. Position moves on the field don't reset the stint.
  4. Longest-stint highlight. The 2 outfield players with the longest current stint (ties included) get a dark outline and pill, so after several quick subs in a row you can see who's been out there longest. GK is left out since they usually play the whole half. Shown in On Field and while building Next Up.
  5. Bench. Each chip shows game minutes plus season minutes underneath. Sorted by fewest game minutes first, unavailable players last (red ✕).
  6. Tapping a player in On Field opens the player sheet (mark unavailable, emergency sub, see minutes). Lineup changes happen in Next Up.
  7. The screen stays awake (wake lock) while a half is running.

8. Flow: queue & make subs

Subs happen at stoppages while the clock keeps running. The coach builds Next Up during play, gets the kids ready at the sideline, and taps Sub now when the ref allows. The shift change is stamped at the clock time of that tap.

Rules of Next Up
  1. Only one queued lineup at a time (no planning further ahead in the MVP).
  2. Next Up is a per-coach draft, saved on that phone, so it survives switching tabs, locking the phone or closing the app. Only what actually gets subbed counts toward the record. (If the sync engine makes a shared draft basically free, we can share it. That's a tech-doc decision.)
  3. If a player in Next Up becomes unavailable before the sub, their slot turns red and "Sub now" is disabled until it's fixed.
  4. Position moves with no one coming in (e.g. Ruby CB→LF) are subs too. They start a new shift so time per position stays accurate.

9. Flow: injury / unavailable / late arrival

Tap any player (in either view) to open the player sheet. What it offers depends on where the player is.

Late arrival: the player is counted as present from the moment they're tapped. Earlier minutes count as "not here", not as bench time.

11. Game review & editing

Mistakes during a game are expected. A game is edited as a timeline of shifts, which matches how coaches remember a game ("we subbed around 10 minutes in, then again near halftime"). It can be edited during the game (⋯ → Game timeline) or after.

Edit rules (UX level)
  1. Editing one shift's lineup does not change later shifts. Each sub records the full lineup at that moment, so there are no surprise knock-on changes.
  2. Unavailable windows are edited the same way (start/end time).
  3. Attendance can be changed after the game too. Unmarking a player who appears in shifts asks for confirmation.
  4. Stats recalculate right away.

12. Stats

Two levels: a team grid for seeing fairness at a glance, and a player detail view. Both work for the season or a single game.

Default fairness metric: "% of available time" = field minutes ÷ (minutes present and available). It doesn't penalize kids for absences, injuries or late arrivals. Raw minutes is always one toggle away.

13. Sign-in, two coaches, dim mode

Sign-in

  1. First launch: enter your email, get a magic link, done. Only invited coaches can see the team. No passwords.
  2. Stays signed in on the device. No sign-in screen at the field.

Two coaches

  1. Both coaches see the same live game on their own phones, updating within seconds when online.
  2. Either one can record subs. In practice one coach holds the clock phone. The other can watch minutes and build their own Next Up draft.
  3. A small indicator in the clock bar shows sync status (synced / offline, will sync). Being offline never blocks recording.

Dim mode

  1. Browsers can't dim the backlight. Dim mode is basically one CSS rule: a fixed black overlay at ~75% opacity on top of the app. It cuts glare and saves battery on OLED phones.
  2. Cheap to build, so it's in the MVP if it stays trivial. Otherwise it gets cut.
  3. Turned on from ⋯, or automatically after ~60s with no tap during a half (one timer). The first tap only wakes the screen and doesn't hit the button underneath.

14. Out of scope (MVP)

  1. Goals, scores, assists or any other game stats.
  2. Lineup suggestions or fairness algorithms (coaches decide, and exported data can go to an outside LLM).
  3. Planning lineups more than one shift ahead.
  4. Multiple teams, seasons or formations in the UI (formation is config only).
  5. Parent or player-facing views.
  6. Data export (CSV/JSON). Planned soon after MVP.
  7. Unavailable reasons, jersey numbers.

15. Decisions log

Decided (v0.2)

  1. Clock counts up and the coach taps End half / End game. No target length, no added time.
  2. Field slots show stint + game total, with the 2 longest outfield stints highlighted. Bench chips show game + season minutes.
  3. No unavailable reasons, just available/unavailable.
  4. Next Up is a per-coach draft unless the sync engine makes sharing free.
  5. No jersey numbers. Last initial(s) can be more than one letter.
  6. Default fairness metric is % of available time. Raw minutes come from the same data.
  7. Dim mode: CSS overlay plus inactivity timer. MVP only if trivial.
  8. Export CSV/JSON: post-MVP.
  9. Halftime counts as nothing.
